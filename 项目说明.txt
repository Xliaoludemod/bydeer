1. 项目简介
----------------------------------------------------------------------
个人摄影作品集，分三个内容层：
  · 首页：首屏轮播 → 第二区域（分栏索引 + 右侧展示图）→ 第三区域
    「片柜」（筛选 + 系列卡片）
  · 专属片柜：按分区（银盐·胶片 / 像素·数码 / 动态·影像）列出成套系列
  · 朋友们：朋友投稿作品的独立入口（首页右上角图标），不和自己作品混排

内容规模（2026-09-30）：
  自己的作品 9 套 121 张（胶片 6 套 101 张 + 数码 3 套 20 张）
  朋友投稿 5 套 26 张
  合计 14 套 147 张照片，另有首屏轮播图 3 张
  动态·影像分区还是空的（显示「视频整理中」）

4. 技术要点（三分钟版）
----------------------------------------------------------------------
  · 无框架、无第三方库。所有页面共用 style.css 和三个 js。
  · 图片显示约定：每张大图 NN.jpg 旁边有个 th/ 子文件夹放同名缩略图。
    代码自动找缩略图，找不到就自动退回大图，所以永远不会破图。
  · 卡片按照片原始比例显示、不裁切；系列页图墙是「同一行等高、
    按比例分宽」的排法。
  · 灯箱（点开照片放大）会显示：作品名 work、器材 gear、署名 credit。

5. 唯一配置源：js/data.js
----------------------------------------------------------------------
改网站内容只动这一个文件，改完不需要构建。里面是一个全局对象 SITE：

  SITE.social[]      导航社交图标
                     url 填 http(s):// 开头 = 新窗口外链
                     填站内路径（如 friends.html）= 当前窗口跳
                     留空或 # = 不跳（填了 tip 则点击复制号码）
  SITE.heroSlides[]  首屏轮播图（数组顺序 = 出场顺序）
  SITE.indexPreview[] 首页第二区域默认展示图
                     放 1 张 = 固定显示；放 2 张以上 = 每 4.5 秒轮换
                     不能留空（空灰框会让人以为网站坏了）
  SITE.sections[]    三个分区（film / digital / motion），每项可带：
                     preview   悬停该分区时右侧展示的图（没配则保持默认）
                     cabinet   点它跳去的专属片柜页，如 cabinet.html?sec=film
                     empty     该分区为空时的占位文字（motion = 视频整理中）
  SITE.series[]      所有系列，顺序 = 片柜出场顺序。每套：
                     slug / title / section / cover / film（胶片型号）
                     photos[] 每张照片：
                       src    必填，如 photos/银盐·胶片/xx/01.jpg
                       gear   必填，器材文字
                       work   作品名（灯箱顶部那行）
                       tags   搜索用标签（数组）
                       note   展签文字（暂未在页面显示）
                       link / code   网盘下载地址和提取码（可空）
                       searchable: false   这一张不进搜索
                     投稿系列再加：
                       credit: "© 某某"      署名
                       searchable: false     整套不进搜索
                       meta: "..."           系列页标题下的小字

注意：用户提供的文字（器材、系列名、胶片名、署名）一律照抄，
不要"规范化"大小写或写法。

6. 照片规格与命名
----------------------------------------------------------------------
  photos/<分区>/<系列>/NN.jpg      大图  长边 2560 · 质量 88 · 约 1MB
  photos/<分区>/<系列>/th/NN.jpg   缩略  长边 900  · 质量 82 · 约 100KB
  photos/首页/0N.jpg               首屏  长边 3200 · 质量 88

  · 单张硬上限 3MB
  · 大图和缩略图同名，缩略图放同目录 th/ 下
  · 只有胶片扫描件才裁黑边，数码原片不裁

7. 搜索（find.html）的工作方式
----------------------------------------------------------------------
三条命中路径，缺一不可：
  1) 概念命中：SYN 同义词表把「安静 / 水边 / 夜 / 黄昏」这类说法
     展开成全部同义词再匹配（快捷标签也必须走这个展开）
  2) 字面命中：双向包含，按「的/了/空格」切词
  3) 分区命中：说「数码」捞出整个 像素·数码 分区，说「胶片/菲林」
     捞出整个 银盐·胶片 分区（新照片自动跟着生效）
给照片写 tags 时，常用概念尽量直接用概念键名本身当标签。

8. 加新照片 / 新系列的流程
----------------------------------------------------------------------
  1) 原片放进一个文件夹（素材库在 N:\2小鹿的网站\片库\，素材库只读，
     只复制不改动）
  2) 跑 tools/prep_photos.py "原片夹" "photos/分区/系列名"
     生成大图 + 缩略图（胶片扫描件加 --crop 裁黑边，数码不裁）
  3) 在 js/data.js 里加这套系列（自己作品插在自己分组里；
     投稿的加 credit 等字段）
  4) 跑 tools/build_series.py 生成独立页
  5) 全站版本号升一号（每个 html 里 ?v=20260927a60 的 a60 部分，
     规则 = 日期+字母序号），然后提交推送

  其它工具：read_exif.py（读拍摄信息）、make_preview.py（拼九宫格
  总览图，别逐张看图）、make_placeholders.py（占位图）。

11. 这台电脑访问 GitHub 的特殊性（重要）
----------------------------------------------------------------------
  · 本机 DNS 拒绝解析 github.com。已在系统 hosts
    （C:\Windows\System32\drivers\etc\hosts）加了一行：
        20.200.245.247 github.com
    （2026-09-30 晚起用这个 IP；之前的 20.27.177.113 当晚就失效了——
     这类 IP 是动态被封的，推不动就换。hosts 原文件备份在同目录
     hosts.bydeer-backup-20260930。）
    哪天又连不上 GitHub：大概率这个 IP 失效了，换一个试试，
    备选：20.27.177.113 / 20.205.243.166 / 140.82.112.3~116.3，
    逐个测 TLS 443 延迟取最低。
  · 推送令牌存在 Windows 凭据管理器
    （GitHub - https://api.github.com/Xliaoludemod），
    是 GitHub Desktop 登录时写入的 OAuth 令牌。
    令牌不要写进任何文件或聊天记录。
  · 提交身份已在仓库级配置（user.name=Xliaoludemod）；
    全局 git 配置的邮箱是空的，别依赖它。
  · github.io 从国内访问偏慢：实测首屏 4MB 图片要等几十秒。
    这是平台特性不是站坏了。治本 = 换国内 CDN（原计划腾讯云
    EdgeOne，需要已备案域名）；治标 = 把首屏图压小。
